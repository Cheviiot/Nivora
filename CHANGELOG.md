# История изменений Nivora

[Каталог](README.md) · [Документация](.github/docs/index.md) · [История commit](https://github.com/Cheviiot/Nivora/commits/main/)

Здесь фиксируются изменения каталога и поведения упаковки.
Текущие версии приложений находятся в README и рецептах; отдельный журнал
каждого upstream-релиза ведёт его разработчик.

## 18 ноября 2026 — надёжная подготовка инструментов и Docker

- Go-зависимости загружаются отдельно от компиляции: не более трёх попыток
  по 180 секунд с короткими паузами. Несовпадение checksum сразу останавливает
  подготовку. Проверка module cache и компиляция выполняются по одному разу;
  изменение закреплённого `go.mod` отклоняется.
- Подготовка Stapler и `stplr-spec` сохраняет прежний бинарник при ошибке
  загрузки, распаковки, компиляции или проверки запуска. Новый файл заменяет
  его атомарно после успешной проверки. Исправлены относительные пути
  и установка `stplr-spec` под явно заданным именем.
- Сборка и lifecycle сохраняют выбранный Docker context, endpoint и TLS
  в отдельном временном конфиге. Личные данные входа в реестры и credential
  helpers не переносятся. Конфиг находится вне передаваемого build context
  и удаляется после завершения операций.
- Добавлены регрессии для сетевых отказов Go, повреждённого cache, сохранения
  рабочего инструмента и согласованности Docker-подключения при подготовке
  и очистке. Технические инструкции описывают новое поведение и диагностику.

## 18 ноября 2026 — Stapler 0.2.0 и сохранность настроек

- Обязательные проверки переведены на Stapler 0.2.0, который поставляется
  в p11. Stable-архивы amd64 и ARM64 закреплены контрольными суммами;
  дополнительная проверка main использует новый фиксированный commit.
  Проверка ARM64 в CI по-прежнему не заявляется.
- Сборка и lifecycle в GitHub Actions используют Docker: Stapler 0.2.0
  требует диапазоны UID/GID, недоступные во вложенном rootless Podman.
  Движок выбирается одинаково для всех этапов и проверяется до сборки;
  локально доступен явный `NIVORA_CONTAINER_ENGINE=docker|podman`.
  Внутренняя песочница Stapler и запрет сети в рецептах сохраняются.
- Parsec сохраняет выбранный пользователем `client_immersive` в JSON и TXT.
  Явный аргумент запуска обрабатывается до изменения настроек. Если JSON
  нельзя прочитать, запуск продолжается без подмены значения и создания
  конкурирующего TXT. Значение по умолчанию добавляется только при отсутствии
  сохранённого выбора. Release пакета повышен до 14.
- Happ отключает и останавливает службу до удаления unit-файла, чтобы
  после удаления не оставалась битая ссылка автозапуска. При обновлении
  состояние включения службы сохраняется. Release пакета повышен до 3.
- Tailscale передаёт путь `/etc/default/tailscaled` в формате, совпадающем
  с `backup`, чтобы RPM помечал файл как `%config(noreplace)`. Проверки
  контролируют эти флаги и сохранение изменённого файла при обновлении
  и удалении, включая переход с предыдущего RPM без config-флага.
  Release пакета повышен до 3.
- Выбор GitHub-релиза нормализует префикс `v` до сравнения версий.
  Отметки draft и prerelease в успешном ответе API больше нельзя обойти
  повторным поиском Git-тегов.
- Проверка источников и ETag учитывает только конечный HTTP-ответ после
  перенаправлений. Ошибка чтения массива источников любой архитектуры
  останавливает проверку, а не оставляет её незаметно пропущенной.
- Дополнены инструкции по Stapler, установке через GNOME Software,
  настройке клавиатуры Parsec, службе Happ и сохранению настроек Tailscale.

## 18 ноября 2026 — надёжность проверок и обновлений

- Автообновление сверяет версию подготовленного рецепта с планом до сборки.
  Если upstream успел выпустить следующий релиз, откладывается только этот
  кандидат; остальные корректные обновления продолжают обработку.
- Lifecycle проверяет свежую установку и переход с предыдущего RPM
  в отдельных чистых контейнерах p11. После установки, обновления и удаления
  проверяется сохранность содержимого контрольного файла пользователя.
- Общий validator проверяет полноту lifecycle-каталога, структуру записей
  и соответствие проверяемых команд матрице поддержки.
- Ручная сборка выполняет общие G0–G2 до сборочных проверок. Выбор приложений
  проходит через общий планировщик: пустой или неизвестный список отклоняется,
  повторы удаляются, все этапы получают одинаковый набор пакетов.
- Скачивание системных RPM допускает два ограниченных повтора при временном
  сетевом сбое. Повторы выполняет APT до установки; установочные хуки
  повторно не запускаются, общий таймаут команды остаётся прежним.
- Руководства согласованы с карточками главной витрины и реальными границами
  проверок. Описаны диагностика upstream и проверка обновления с конкретного RPM.

## 17 ноября 2026 — ALT p11 и переработка сопровождения

### Каталог

- Единственная целевая платформа — ALT Linux p11. Рецепты, зависимости,
  образы сборки и обязательные проверки согласованы с этой веткой.
- Удалены Casement, DistroShelf и GitHub Desktop: рецепты, иконки, хуки,
  специальные тесты, отдельные сборочные workflows и логика обновления.
- В каталоге осталось 12 приложений. Для всех предусмотрены обязательные
  проверки amd64; у семи сохранена предварительная поддержка ARM64.
- Пользовательские описания и AppStream приведены к актуальным первичным
  источникам. Antigravity обозначен как App, AniDesk — как неофициальный
  клиент Anixart.

### Документация

- Главный README заново оформлен как каталог приложений с версиями,
  архитектурами и ссылками.
- Переписаны все карточки приложений.
- Добавлена общая навигация, отдельные руководства по установке, пакетам
  и диагностике. Заново написаны правила участия, обслуживания и безопасности.
- Рабочая ветка сопровождения — `main`.

### Автоматическое обслуживание

- К почасовой проверке обновлений добавлен ежедневный полный прогон каталога
  на p11.
- Успешная проверка снимает паузу только для актуального `main` и связанной
  истории. Устаревшие результаты не меняют состояние текущего каталога.
- Во время паузы доступно исправляющее обновление источников: перед его
  публикацией проверяется весь каталог и точное дерево изменений.
- Исправлены обнаружение опубликованного Telegram-архива при HTTP/2,
  согласование AniDesk `debian_version` и fallback на Git-теги без префикса `v`.
- Удалены специальные пути сборки и публикации исключённых приложений.
- Подготовленный образ p11 повторно используется внутри одного CI job,
  при этом сборка и lifecycle работают в новых контейнерах. Добавлен один
  ограниченный повтор обхода зеркал ALT после временного сбоя индексов.

Подробное расписание, порядок публикации и восстановления:
[автономное обслуживание](.github/docs/maintenance.md).
