# История изменений

В файле фиксируются значимые изменения Nivora.

## 2026-08-13 — ClaudeAlt не собирался, Parsec не ставился на Sisyphus

Аудит на реальных сборках в контейнерах ALT (не только чтение рецептов)
вскрыл две регрессии, из-за которых пакет либо не собирается, либо не
устанавливается на целевой системе — то есть не даёт того же функционала,
что оригинальный файл на своей системе.

### Исправлено

- `claude-alt`: `patch-asar.py` после обновления `claude`/`claude-alt` до
  `1.26832.0` (см. запись от 2026-08-11) перестал собираться вообще —
  `stplr build` падал на `unexpected ClaudeAlt patch counts`. Патч был
  завязан на буквальный минифицированный фрагмент кода
  (`P.app.isPackaged||P.app.setName("Claude");RRn();`), а такие
  однобуквенные идентификаторы Vite/esbuild перевыдаёт на каждой
  пересборке апстрима — якорь совпадал только со сборкой, под которую
  был написан. Патч переписан на поиск структурного паттерна через regex
  (`(\w+)\.app\.userAgentFallback=\`\$\{\1\.app\.userAgentFallback\}
  MSIX\``) с захватом текущего имени переменной `app`, а не на точную
  строку — привязка теперь к реальному вызову Electron API, а не к
  случайному имени функции. Прогнано на реальном `app.asar` версии
  `1.26832.0`, скачанном напрямую с `downloads.claude.ai`; полная
  пересборка через `clean_build.sh` и установка получившегося RPM в
  чистом контейнере ALT Sisyphus проверены отдельно.
- `parsec`: `deps_altlinux` требовал `libavcodec61`, которого нет в
  текущем ALT Sisyphus (там уже `libavcodec62`; на ALT p11 всё ещё
  `libavcodec61`) — `apt-get install` пакета `parsec` падал на
  Sisyphus с ошибкой «пакет не найден» ещё до копирования файлов, то
  есть пакет не ставился на этой ветке ALT вообще. Заменено на
  `libavcodec62 | libavcodec61 | libavcodec60`, как и в `deps_debian`,
  где для той же библиотеки уже была цепочка совместимых soname.
  Проверено install'ом собранного RPM в чистом контейнере
  `registry.altlinux.org/sisyphus/base` — бинарник `parsecd` линкуется
  без единой отсутствующей библиотеки.
- `claude-alt`: `deps_altlinux` (и то же для остальных дистрибутивов) не
  включал ни один backend `xdg-desktop-portal` (только сам
  `xdg-desktop-portal`, без `-gtk`/`-gnome`/`-kde`), а `opt_deps` был
  вообще пустым — при том что `claude` для того же самого upstream-DEB
  (идентичные checksums) требует backend порталa жёстко и рекомендует
  звук, appindicator-трей, keyring и весь стек Cowork VM sandbox
  (`qemu-system-x86`, `ovmf`, `virtiofsd`). `patch-asar.py` отдельно
  переименовывает VM-сокет в `claude-alt-cowork-vm.sock` именно для
  того, чтобы эта песочница у ClaudeAlt работала независимо — то есть
  функциональность задумывалась, но зависимости для неё не были
  объявлены. `claude-alt/Staplerfile` синхронизирован с `claude` по
  этим полям; `release` обоих пакетов повышен.

## 2026-08-11 — Обновление версий, фикс определения версии по GitHub-релизам

### Изменено

- `claude`/`claude-alt`: `1.24012.11` → `1.26832.0`.
- `opencode`: `1.18.15` → `1.18.16`.

### Исправлено

- `github_latest_release()` в `package_updates.sh` брал первый нечерновой
  нестабильный релиз репозитория без проверки, что тег вообще похож на
  версию. Для `vintner` это ошибочно возвращало `wine-v1` — отдельный
  релиз с bundled-сборкой Wine для собственной функции `vintner`
  (`internal/download/wine.go`), а не версию самого инструмента. Тег
  теперь должен содержать `ЦИФРЫ.ЦИФРЫ` — под это подходят все реальные
  схемы версионирования в каталоге (`v0.5.0`, `26.721.81911`,
  `release-3.6.3`), но не `wine-v1`.
- Первая попытка обновить `opencode` собрала правильную версию и amd64-
  контрольную сумму, но оборвалась по таймауту на arm64-чексумме, оставив
  несовпадающую пару версия/checksum — досчитана вручную и проверена
  перед коммитом.

### Изменено

- `/usr/bin/vesktop` больше не симлинк, а wrapper-скрипт: добавляет
  `--gtk-version=4` (Chromium сам откатывается на GTK3, если GTK4 не
  установлен — безопасно всегда) и `--ozone-platform=wayland` под
  реальной Wayland-сессией. Electron физически не может рисовать
  настоящую libadwaita/CSD-рамку окна ни при каких флагах — это
  приближает рендеринг к нативному настолько, насколько позволяет
  Electron, не более.

## 2026-08-08 — DistroShelf теперь собирается в CI

### Изменено

- `distroshelf` больше не собирается из исходников при установке —
  реальная установка на ALT p11 падала, потому что там нет пакета
  `vte3-gtk4` (GTK4-флейвор VTE) вообще. Пакет теперь собирается CI
  Nivora (`.github/workflows/distroshelf-linux.yml`, по образцу
  `github-desktop`) в официальном контейнере ветки ALT p11 — не
  Sisyphus/Fedora/Ubuntu, у них более новый glibc, несовместимый в
  обратную сторону — со встроенной сборкой VTE-GTK4 0.82.1 из исходников
  и фичами `gtk4`/`libadwaita`, понижёнными до версий, реально доступных
  на p11 (`gnome_48`/`v1_8`). Результат публикуется в собственном релизе
  Nivora, `Staplerfile` его просто скачивает и переупаковывает.
- `deps_altlinux` пакета: `vte3-gtk4` убран (bundled), добавлен `liblz4`
  (реальная runtime-зависимость собранного VTE). `build_deps` вернулся к
  минимальному `binutils` — тулчейн для сборки больше не нужен конечному
  пользователю.

Проверено вживую: полный CI-прогон опубликовал реальный релиз
(`distroshelf-1.5.2-linux`), `clean_build.sh`/`verify_artifacts.sh` собрали
из него RPM, а сам RPM установлен и запущен в чистом контейнере ALT p11
только с четырьмя задекларированными runtime-зависимостями.

## 2026-08-07 — DistroShelf

### Добавлено

- Пакет `distroshelf` — GTK4/libadwaita клиент для управления контейнерами
  Distrobox (GPL-3.0-or-later, GitHub Releases).

Первый пакет в каталоге, собираемый из исходников (meson + cargo), а не из
готового upstream-бинарника: upstream публикует только vendored source
tarball, без прекомпилированного Linux-релиза. Рецепт и полная изолированная
сборка проверены через `clean_build.sh`/`verify_artifacts.sh`, бинарник
протестирован на чистом рантайме без build-зависимостей. Подробности — в
[`.github/docs/maintenance.md`](.github/docs/maintenance.md#сборка-из-исходников).

## 2026-08-06 — Vesktop вместо официального Discord

### Добавлено

- Пакет `vesktop` — неофициальный клиент Discord от команды Vencord
  (GPL-3.0-or-later, GitHub Releases, `amd64`/`arm64`).

Официальный `.deb`/`.tar.gz` Discord оказался непригоден для модели доверия
Nivora: это самообновляющийся bootstrap (~2 МБ), который при первом запуске
сам скачивает настоящий Electron-клиент с CDN Discord и дальше сам себя
обновляет — вне контроля Stapler, без SHA-256-пиннинга payload на этапе
сборки рецепта. Публичного лёгкого API для проверки актуальной версии у
этого протокола тоже нет. Vesktop публикует настоящие статические сборки на
GitHub Releases с фиксированной версией — как и любой другой пакет Nivora.

## 2026-07-25 — Vintner

### Изменено

- Пакет `msvc-go-wine` переименован в `vintner` вслед за ребрендингом
  апстрима (github.com/Cheviiot/vintner); `replaces` обновлён для чистого
  перехода при обновлении.
- Версия поднята до `0.2.0`: добавлена поддержка сборки KMDF/UMDF-драйверов
  через Windows Driver Kit (`download --with-wdk`), короткие алиасы команд
  и локализация CLI на английский и русский (`VINTNER_LANG`).
- Версия поднята до `0.3.0`: пакет теперь сам регистрирует автодополнение
  для bash (`/usr/share/bash-completion/completions/vintner`) и zsh
  (`/usr/share/zsh/site-functions/_vintner`) через хелпер Stapler
  `install-completion` — работает сразу после `stplr install`, без
  ручного `source <(vintner completion bash)`. Также добавлена корректная
  остановка процессов Wine при завершении `vintner` по PID.
- Версия поднята до `0.3.1`: исправлен реальный баг в `toolrelay.exe` —
  определение `mt.exe` по имени файла никогда не срабатывало (путь
  приходил с прямыми слэшами, а проверка искала обратный), из-за чего
  перевод кода возврата `mt.exe` для совместимости с CMake фактически не
  работал ни разу. Найдено и исправлено при реальной сборке движка Ogre3D
  через CMake+Ninja+cl.exe.
- Версия поднята до `0.4.0`: добавлена поддержка DirectX SDK (июнь 2010)
  для сборки устаревшего кода на D3DX9 (`download --with-dxsdk`), и
  алиасинг старых имён PlatformToolset (v90–v143) на единственный
  установленный компилятор — теперь старые `.vcxproj`, закреплённые за
  давними версиями тулсета, тоже собираются. В зависимости добавлен
  `cabextract` (нужен рантайму для `--with-dxsdk`).
- Версия поднята до `0.5.0`: инструменты MSVC теперь можно вызывать без
  добавления `<dest>/bin/<arch>` в PATH — напрямую как `vintner cl ...`,
  `vintner msbuild ...` и т.д. Добавлена команда `vintner doctor`,
  диагностирующая неисправную настройку wine/toolchain. `download` теперь
  докачивает прерванные загрузки вместо перезапуска с нуля, а
  `download`/`install` берут файловую блокировку на каталог назначения,
  чтобы два параллельных запуска не повредили дерево файлов. Ошибка
  «wine не найден» теперь называет конкретный пакет для установки.
  Wine-процессы больше не зависают навечно при обрыве сборки (принудительно
  отключён node reuse MSBuild, добавлена поддержка таймаута через
  `VINTNER_TIMEOUT`).
